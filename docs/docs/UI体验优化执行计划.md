# UI 体验优化执行计划

> 目标：把「给评审看的实现说明」改成「给用户看的产品界面」
> 文档版本：**v1.0**
> 编制日期：2026-09-21
> 适用范围：`entry/src/main/ets/**`（页面 / 组件 / 文案），不改动领域逻辑与数据模型
> 关联文档：`docs/需求规格说明书.md` v4.0、`docs/架构设计说明书.md`、`docs/系统设计说明书.md`
> 定位方式：下文用「文件 › 文案片段」定位，便于在代码中检索（行号随改动会漂移，故不写死）

## 1. 背景与目标

当前 Demo 已跑通「拍照 → 识别 → 确认 → 生成 → 候选 → 详情 → 补货 → 我的」全链路，但界面文案与页面组织是按**规格条款**写的，不是按**用户认知**写的。典型表现：

- 界面上出现 `NFR-11 / UC-29`、`Demo 输入回退`、`（不计入分母）` 这类只有评审/开发者看得懂的内容；
- 内部状态（图像来源、快照新鲜度、差集结果）被原样平铺成文字行；
- 每个页面都是「标题 + 一堆控件 + 一堆说明文字」的堆砌，缺少主次、动线和系统级导航。

本计划要做两件事：

1. **清理提示性词语**：用户可见区域不再出现规格编号、工程术语、实现口径与自我说明。
2. **重做页面体验**：建立导航骨架、设计令牌、状态表达（加载/空/错/成功），让每页只承担一个用户任务。

### 2.2 问题二：页面不像真实产品

**导航缺失**
- 首页顶栏直接塞 `Button('我的')`，二级页各自实现 `Button('返回')`；
- 8 个页面在 `resources/base/profile/main_pages.json` 中同级平铺，没有 Tab / Navigation 层级；
- 未使用系统返回手势与安全区适配。

**信息架构堆砌**
- 首页同时承载：快照头、来源标签、库存清单、消耗进度条、差集文案、补货提示、两个跳转按钮、演示数据按钮；
- 生成设置页把人数、饭量、便当、缺材策略、忌口平铺成裸控件，没有分组与默认值收敛；
- 「我的」页把开关、省钱公式、阈值、Key、删除数据全部等权排列。

**状态表达缺失**
- 无加载态（识别/生成是同步阻塞 + toast）；
- 无错误态与重试入口（失败只 `promptAction.showToast({ message: '页面跳转失败' })`）；
- 无空态插画，仅 `Text('🧊')`（`view/Widgets.ets` › `EmptyState`）；
- 无下拉刷新、无长按/左滑删除、无撤销；仅「删除数据」有二次确认。

**视觉不成体系**
- 16 进制色值（`#2E7D32`、`#F0F0F0`、`#8A8A8A` 等）硬编码在 8 个页面中，`resources/base/element/color.json` 未用于界面；
- 无图标体系，全部用文字按钮（`返回` / `我的`）；
- 字号/圆角/间距无令牌，卡片圆角在 12/14 之间漂移。

## 3. 优化原则（改造时的判定准则）

1. **说人话**：用户可见区域禁止出现规格编号、`Demo`/`Mock`/`回退`/`降级`/`分母`/`口径`。
2. **只讲收益，不讲机制**：把「关闭后 X 停用」写成「关掉后不再推荐需要买的食材」。
3. **内部状态转译**：来源、新鲜度、差集等内部字段转成「时间 + 动作」语言，或降级为视觉元素（角标/颜色）而非文字。
4. **一屏一任务**：每页只保留一个主操作；次要信息折叠或移到「我的」。
5. **遵循 HarmonyOS 设计规范**：底部 Tabs 承载一级页面，二级页面用 Navigation / 系统返回，统一安全区与沉浸式状态栏。
6. **文案集中管理**：可复用文案迁移到 `resources/base/element/string.json`，页面只引用资源，避免再次硬编码。

## 5. 页面重构设计

### 5.1 全局骨架（新增）

- 新增 `entry/src/main/ets/view/Theme.ets`：设计令牌（色板、字号、间距、圆角、阴影）；同步在 `resources/base/element/color.json` 落地主色与语义色（成功、警告、危险、文字三级）。
- 一级页面改为 **Tabs 底部导航**：`今天`（Index）/ `生成`（GeneratePage 入口）/ `我的`（ProfilePage）。
- 二级页面（CapturePage / ReviewPage / CandidatePage / RecipeDetailPage / ReplenishPage）改为 Navigation push，统一返回与安全区。
- 新增通用组件：`AppBar`（标题 + 返回 + 右侧动作）、`Card`、`PrimaryButton`、`LoadingView`、`ErrorView`、`EmptyView`（带插画位）、`ListRow`（图标 + 主文案 + 副文案 + 右箭头）。

### 5.2 首页（`今天`）

自上而下：

1. `AppBar`：`冰箱清库存` + 右侧图标按钮（历史/刷新）。
2. **库存卡**：标题 `现在的库存` + 副文案 `2 小时前拍的`；食材列表（品类 + 余量 chip + 临期角标），支持左滑删除并给撤销提示。
3. **本周小结卡**：`这周用掉了 3 样` + 进度条；差集明细折叠在「查看明细」。
4. **补货卡**（仅触发时出现）：`再买一两样就能做` + `还差：土豆、鸡蛋` + 主按钮 `看看买什么`。
5. **底部固定主按钮**：`拍照更新库存`。
6. 空态：`EmptyView` 用 `🧊` 作插画位 + `拍一张冰箱照片，看看现在有什么菜` + 主按钮 `拍冰箱`，`试用示例数据` 作为卡片底部次级文字按钮。

## 7. 验收标准与验证方式

**功能不变式（必须保持）**

- 历史快照不得冒充当前库存（只改表述，不改行为）；
- 补货分支最多 2 样、标注来源与推广性质、不拉起外部 App；
- 省钱成就仅在「我的」页出现，不出现在首屏或启动弹窗；
- 步骤 ≤ 8、余量档位 ≤ 5、无数字键盘；
- 无 API Key 时仍可完整走通主链路（Mock 能力保留，但界面不出现 `Mock` 字样）。

**验证步骤**

1. 文案自查：对 `entry/src/main/ets` 执行 §6-P0 的关键词检索，确认仅注释命中。
2. 静态检查：`builtin_check_editor_errors` 逐页检查。
3. 构建：`builtin_execute_build_command` 通过。
4. UI 验证：`builtin_ui_verification` 跑三条用例——
